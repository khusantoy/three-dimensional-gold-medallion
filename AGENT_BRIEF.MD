## 1. Mission

Build a Dart/Flutter subsystem that turns 2D vector art (SVG path data, or an SVG file,
or a `ui.Path`) into a **physically-lit 3D gold medallion** the user can rotate with a
finger.

The reference implementation is **Minted** by Haplo LLC — a Swift/SwiftUI package,
MIT licensed:

    https://github.com/haplollc/Minted

It is ~2,550 lines of production Swift across 11 files. Read it as a **design document**,
not as code to transliterate. The interesting parts:

| File | What to take from it |
|---|---|
| `Sources/Minted/SVGPath.swift` | SVG `d` grammar coverage — which commands must be handled. Do **not** port it; Dart already has this (see §4). |
| `Sources/Minted/CoinDesign.swift`, `CoinDesign+Paths.swift` | How a coin is composed: silhouette, rim bands, enamel cells, raised gold wire. Ports nearly 1:1. |

## 3. Verified technical findings — read before planning

These were confirmed by reading the source. They will save you days.

**3.1 `flutter_scene`'s `ExtrudeGeometry` will NOT do what its name suggests.**
It lives in `lib/src/geometry/swept_geometry.dart`. It **sweeps a profile polygon along a
path** (a tube with a custom cross-section) — it is not SceneKit's `SCNShape`, which
extrudes a flat outline to a depth. Worse, its end caps are generated by `addFanCap`, and
the doc comment states plainly: *"End caps assume a convex profile."*

Coin silhouettes are almost never convex (a heart, a star, a landmark). A triangle fan will
produce garbage. **You must write your own polygon triangulation** (ear clipping / earcut,
with hole support) and build the mesh yourself via `MeshGeometry.fromArrays(...)`, which is
public. This is the single biggest piece of work the reference implementation got for free
from `SCNShape` and you will not.

**3.2 The PBR and image-based lighting you need already exist — use them, don't rebuild.**
`lib/src/material/` contains `physically_based_material.dart`, `dfg_lut.dart` (Karis
split-sum BRDF LUT), `diffuse_sh.dart`, `environment.dart` with `prefilterEquirectRadiance`,
and `hdr_decoder.dart` / `exr_decoder.dart`. This is the equivalent of Minted's
`scene.lightingEnvironment`.

**An HDR/EXR environment map is mandatory, not optional.** Gold at metalness 1.0 with no
environment to reflect renders as a flat dark disc. Sourcing a suitable studio HDRI (soft
boxes, a window streak, a warm floor bounce — per Minted's README) is part of milestone 1,
not an afterthought. Use a permissively licensed one (e.g. Poly Haven, CC0) and record its
source in the README.

**3.3 Flutter GPU must be explicitly enabled on native platforms.**
Impeller is the default, but Flutter GPU needs a flag in `AndroidManifest.xml` and
`Info.plist`. The exact keys are in the flutter_scene README section "Enable Flutter GPU".
Read it — do not guess the key names. Web needs no flags (WebGL2 backend).

**3.4 Engraved lettering along an arc is not feasible in v1. Drop it.**
Minted uses `CTFontCreatePathForGlyph` to get real glyph outlines. Dart has **no public
glyph-outline API**. Working around it means parsing the TTF `glyf` table yourself. Out of
scope. Do not attempt it, do not stub it.

**3.5 Not every SVG can become a coin.**
Open contours, zero-width strokes, hair-thin spires — these fail tessellation, and a shape
that fails to tessellate renders as *nothing at all*. The geometry layer must return an
explicit error describing *why* a given input failed. Never return an empty mesh silently.

## 4. Architecture — two layers, keep them separate

**Layer A — geometry (pure Dart, no Flutter, no flutter_scene).**
Input: SVG path data / SVG file bytes / a list of contours.
Output: `Float32List positions`, `normals`, `texCoords`, `List<int> indices`, plus an
explicit success/failure result type.

This layer must be **unit-testable with `dart test`, with no widget and no GPU.** Test it
on known-hard shapes: a concave heart, a shape with a hole (a ring, the letter O), a
self-intersecting path, an open contour.

For SVG parsing, evaluate existing Dart packages before writing your own — start with
`path_parsing`, and look at how `flutter_svg` handles the full `d` grammar. Report what you
find and recommend; do not silently write a parser from scratch.

**Layer B — rendering (flutter_scene).**
Takes Layer A's arrays, builds `MeshGeometry.fromArrays`, attaches a physically based gold
material, sets up scene + camera + environment, exposes a Flutter widget.

The boundary between A and B must be a plain data struct. If we later abandon flutter_scene
for a fragment-shader approach, Layer A must survive untouched.

Directory layout:

```
<<project root>>/
  packages/
    <<package_name>>/          # local path dependency, NOT published yet
      lib/
        src/geometry/          # Layer A
        src/render/            # Layer B
      test/
      example/                 # optional, only if it helps you verify
```

Wire it into the app's `pubspec.yaml` as a `path:` dependency. Do not publish anything.

## 5. Milestone 1 — vertical slice (this is ALL you do first)

The narrowest possible end-to-end path. **No SVG. No enamel. No text. No image analysis.**

1. Add `flutter_scene`, enable Flutter GPU on iOS and Android.
2. Add a studio HDRI to assets and load it as the scene environment.
3. Generate a **plain circular disc** mesh with thickness, procedurally (a circle is convex,
   so this needs no triangulator yet — that is the point).
4. Gold physically based material: metalness 1.0, low roughness.
5. A widget showing it, wrapped in flutter_scene's `CameraControls` with an
   `OrbitCameraController` so I can drag to rotate. (Both exist:
   `lib/src/widgets/camera_controls.dart`, `lib/src/camera_controllers/orbit_camera_controller.dart`.)
6. Drop that widget on one screen of the app.

> **STOP.** Tell me how to run it. I will send screenshots from a real iOS device and a real
> Android device. Do not start milestone 2.

**Definition of done:** the disc looks like *metal* — reflections sweep across the surface as
it turns — on both platforms. If it looks like a flat grey circle, the environment or the
material is wrong and nothing after this matters.
